1. Project Goals & Enterprise Motivation

In modern radar telemetry, acoustic array processing, and RF spectrum monitoring, hundreds of time-series channels must be transformed into the frequency domain with sub-millisecond latency.

  • Objective: Architect a multi-stream GPU spectral pipeline utilizing NVIDIA cuFFT and custom CUDA kernels.
  • Pipeline Stages: Async Host-to-Device DMA → Hamming Window Kernel → Batched R2C cuFFT → Spectral Magnitude & Noise Gate → Device-to-Host Gather.
  • Scale: Process 100+ multi-harmonic signals (1.63M samples) without host thread blocking.
SLIDE 02 / 05
2. Mathematical Formulation & STFT Flow

Each discrete time-domain signal $x[n]$ is segmented into overlapping frames of length $N = 1024$ with a hop stride $H = 512$ (50% overlap):

  • Hamming Windowing: $x_w[n] = x[n] \cdot (0.54 - 0.46 \cos(2\pi n / (N-1)))$ minimizes spectral leakage across adjacent frequency bins.
  • Real-to-Complex FFT: Exploits conjugate symmetry ($N/2 + 1 = 513$ unique bins) via cufftExecR2C, cutting memory footprint in half.
  • Log-Power & Gate: $P_{dB}[k] = 10 \log_{10}(|X[k]|^2 / N)$, clamping bins below threshold $\tau_{dB}$ to $-65\text{ dB}$.
SLIDE 03 / 05
3. Multi-Stream Concurrency & Pinned Memory

Saturating 40 Streaming Multiprocessors on the NVIDIA Tesla T4 requires hiding PCIe bus latency behind active math computation:

  • Page-Locked Host Memory: Allocated via cudaMallocHost so the GPU DMA copy engines transfer data without CPU page-fault overhead.
  • 4-Way Stream Round-Robin: Signals are dispatched across 4 cudaStream_t queues, enabling simultaneous H2D, Compute, and D2H phases.
  • Batched cuFFT Plans: Replaces 31 individual kernel launches per signal with a single batched cufftPlanMany execution.

4. Empirical Benchmarks on Tesla T4

Profiled on an NVIDIA Tesla T4 (Turing Compute 7.5, 40 SMs, 16 GB GDDR6):

  • End-to-End Signal Latency: 1.41 ms average per 16,384-sample channel.
  • Sustained Throughput: 11.60 Megasamples/sec across all active streams.
  • Stream Scaling Speedup: Achieved a 3.46x speedup using 4 asynchronous streams compared to default stream serialization.
